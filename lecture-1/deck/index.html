Start with the left column. It is the first two periods on slides 10 and 11: the executable era proper, and then the period in which the file diversified into documents, scripts and exploit objects but remained the deliverable. For roughly fifteen years the attacker's problem was to get their own code onto the victim's machine and run it, because the victim's machine offered little else to work with. PowerShell did not ship by default until Windows 7 in 2009, remote-management tooling was not ubiquitous, and business data lived on the host rather than behind cloud APIs. Email attachments, drive-by downloads, removable media, worms, and bundled installers all delivered a program. The program was the capability, so the program was the right thing to catch.

The right column is why the industry could build on that. Files cross the boundary the defender controls, persist long enough to inspect, hash identically everywhere, and can be scanned before they run. Samples flow between vendors, signature databases grow, sandboxes detonate them, and supervised datasets are built from them. Connect this to antivirus hooks, sample exchanges, and later the public PE datasets covered in Lecture 3.

Stop here. Do not preview how the model breaks; the next four slides show it period by period, and slide 14 draws the list. The only forward-looking sentence this slide needs is that the model held for about fifteen years.

Operating system
  • Windows XP (2001): users run as administrator, autorun on, firewall present but off by default until SP2 (2004) turns it on and adds DEP (no-execute memory)
  • Vista (2007): UAC (consent prompts for administrative actions), mandatory 64-bit driver signing, ASLR (randomized memory layout); kernel-patch protection carried over from 64-bit XP and Server 2003 SP1 (2005)
  • Windows 7 (2009) ships PowerShell by default
Internet
  • Broadband replaces dial-up
  • IE6, ActiveX, Flash, Java and Acrobat plugins
  • HTTP in plaintext; HTTPS only for login and payment
  • Email is the delivery channel
Security products
  • Signature antivirus, then heuristics and emulation to see through packers
  • Outlook (2000) and mail gateways, then Gmail (2004, zips included), block executable attachments; messengers filter unsafe transfers after the 2005 IM worms; Office macro security ends the first script wave
  • Personal firewalls and HIPS
  • Anti-spam gateways
  • Network intrusion detection and prevention (IDS/IPS) on plaintext traffic
  • Cloud reputation and file prevalence arrive at the end of the decade

The capability travelled as an executable, rarely a plain attachment: by download, worm, USB or browser exploit. The victim ran as administrator, the network was unencrypted, and the products of the decade inspected files and payloads.

Read the five tracks as one system, starting with the money. The attacker's unit was the executable because the victim ran as administrator on a machine with no built-in tooling worth abusing, received email and browsed with plug-in-heavy browsers, and the network carried everything in the clear. The defenses that mattered were exactly those built on that unit: file scanners, payload signatures, spam filters.

Motive explains the volume. The decade opens with worm authors seeking notoriety and closes with a criminal market. Adware and pay-per-install paid per infected machine; spam botnets rented out capacity; the same botnets sold DDoS, first as extortion of online businesses and then as a service for hire (Ancheta, indicted in November 2005 for selling botnet access for DDoS and spam, was the first US prosecution of its kind); click fraud monetized browsers; banking trojans and carding monetized credentials. Once an infection was worth a few cents to a few dollars, the attacker's problem became scale, and scale is what produced botnets and server-side polymorphism. The product was the victim's machine, its bandwidth and what it typed.

Worms, then botnets. The first half of the decade belongs to the worms: Code Red and Nimda in 2001, Slammer and Blaster in 2003, Sasser in 2004, each exploiting an unpatched service on a machine with no firewall and spreading with no user action. XP SP2 turning the firewall on in August 2004 is the defender's answer, and the big network worms go quiet until Conficker finds MS08-067 in 2008. The second half belongs to the botnets. The IRC bot families (Agobot, SDBot, rxbot) made the compromised machine report to a channel and take orders, which is what turned infections into inventory that could be rented for spam, DDoS and installs; Ancheta was prosecuted for exactly that trade. Storm, Zeus, Conficker and Koobface are the mature form: the machine is the product and the binary is disposable.

Each block got an answer. Outlook blocked executable attachments in 2000 and Gmail from 2004, zips included; the mass-mailers switched to zip within weeks (MyDoom, January 2004) and to password-protected zips with the password shown as an image (Bagle, February to March 2004). When the IM worms of 2005 made MSN Messenger filter .pif and executable transfers, Kelvir was already sending a link instead. Exploit documents (a Word zero-day in May 2006, PDF in November 2008) and MPack, the first exploit kit sold commercially (2007), are the same answer with a different container: the file diversified as soon as the executable was blocked, which is why slide 14's first bar starts in this period and not in 2010.

Within the decade the attacker moved three times inside the file:

  • Packers and protectors made the bytes on disk stop matching the code that ran. Antivirus added emulation and generic unpacking: the scanner ran the file a little to see it.
  • Rootkits and bootkits made the live system lie about which files and processes existed. The Sony BMG case in 2005 made the technique public. Defenders inspected raw disk and memory from outside the lying layer, and Microsoft's 64-bit kernel-patch protection (2005) and Vista's mandatory driver signing (2007) were in part a response.
  • Botnets and server-side polymorphism turned the host into a rented commodity and gave every victim a unique binary. The asset was the command-and-control infrastructure; the binary was disposable. This broke hash and byte signatures operationally and produced reputation and prevalence systems (McAfee Artemis in 2008, Symantec Quorum and Insight in 2009–2010), cloud lookups, generic detections, and pushed machine learning on file features from research (first papers in 2001) toward products (from about 2012). Lecture 3 picks that up.

The operating-system row explains why so much was possible: administrator by default, autorun, and no exploit mitigations until SP2 and Vista. Vista's UAC and driver signing were unpopular precisely because they took privileges away from the model attackers had been enjoying.

Two kinds of payoff now coexist. Crime industrializes into a service economy: exploit kits are licensed by the year or rented by the day, installs are bought and sold, and point-of-sale malware turns retail breaches into card data. Bitcoin, usable at scale from about 2013, is the enabler that ransomware had been waiting for: CryptoLocker is the first campaign in which the victim pays the attacker directly rather than the attacker monetizing the victim's machine through a third party. At the same time the APT era brings an adversary whose payoff is strategic, not financial: espionage, intellectual property, sabotage. The same tradecraft serves both, which is one reason a file verdict cannot tell you what you are dealing with. North Korea's Bangladesh Bank heist in 2016 shows a state using the APT toolkit for money, and the Ukraine grid attack of December 2015 is the first confirmed outage caused from a keyboard. Banking fraud is the steady revenue underneath all of this: the Zeus source leak of 2011 gave everyone a kit, GameOver Zeus ran the peer-to-peer version until Operation Tovar took it down together with the CryptoLocker infrastructure in June 2014, and the police lockers of 2012, a fake fine paid by prepaid card, were the extortion model that Bitcoin replaced.

Three more shifts happen in this period and they interact.

The adversary changed. Operation Aurora in January 2010, Stuxnet that June and the APT1 report in 2013 made the funded, persistent, mission-driven team the reference adversary. Multi-stage tooling, zero-days, stolen signing certificates, months of dwell. A file verdict says nothing about who is behind it or what they want. The kill chain paper in 2011, threat intelligence as a discipline, and ATT&CK in 2015 are the defensive response: the campaign, not the file, becomes the unit of analysis. That is the next module.

The file diversified; it did not disappear. Be careful not to overstate this period. The main deliverable was still a file. What changed was the kind of file and the channel, and the cause was defensive. Outlook had blocked dangerous attachment types since 2000 and mail gateways followed, so by the late 2000s an executable attachment rarely reached a user. Attackers diversified the container instead: archives wrapping executables, PDF and Office exploit documents, macro documents again from 2014, JavaScript, VBScript and HTA downloaders, shortcut files, and the browser through exploit kits. This was itself a second wave; macro viruses from 1995 and the VBScript worms of 2000–2001 had shown that a document or script could carry the capability before Office macro security and attachment blocking pushed attackers back to executables for a decade. Exploit kits delivered through Flash, Java and Internet Explorer and then dropped an executable, so the first artifact was an exploit object rather than an attachment. Malicious PDFs and Office exploits, then macro documents from 2014 when plug-ins declined, carried the capability in a document. Scripts, archives and JARs replaced the bare executable in email. Ransomware arrived as a file. A sandbox that detonated documents, archives, scripts and the executables they dropped was therefore the right control for this period, which is why it became the premium control around 2013 to 2016.

The exit from the file begins at the end. Windows 7 had put PowerShell on every machine. PowerSploit in 2012, Cobalt Strike the same year and Empire in 2015 made reflective loading and memory-only payloads a framework feature, Poweliks and Kovter persisted in the registry with no executable on disk, and Mimikatz made stolen credentials cheaper than exploits. The term "living off the land", using the tools already on the victim's machine instead of bringing malware, was coined in 2013. In this period these were the tradecraft of advanced operators and red teams. They become standard in the next period, and that is when the sandbox is starved. Slide 21 covers the mechanism. Mirai, in the last months of the period, is the other foreshadowing: a botnet built from cameras and routers that can never run an agent, the edge arriving first as a weapon and, by 2026, as a product sold from the factory (XCPE, slide 13).

The internet encrypted itself for a reason. The Snowden disclosures from June 2013 turned HTTPS from a login-page feature into the default: the IETF declared pervasive monitoring an attack, Let's Encrypt made certificates free, and half of page loads were encrypted by late 2016. Slide 22 picks up what that did to the network sensor.

Microsoft's AMSI (the Antimalware Scan Interface, which hands scripts to the antivirus at run time) and script block logging in 2015 are the operating system moving the sensor to where the capability went, and Windows 8 had already made Defender a full antivirus on every machine, with Defender ATP adding EDR to Windows 10 in 2016; that is why the next period can say Windows closed the easy paths. EDR and Sysmon are the product market doing the same, but note the premise: EDR (endpoint detection and response) was named in 2013 because defenders had accepted that antivirus would not stop a determined adversary and that breaches had to be detected and investigated after the fact. It is a different control, not a next-gen antivirus. Slide 21 develops this.

The money moved from the consumer to the enterprise. In the previous periods the attacker monetized the victim's machine or credentials through a third party. Now the victim organization pays the attacker directly, and the sums are set by what a company will pay to recover or to keep data private. That single change explains the period. This is the criminal landscape of the period the way botnets were for 2005 to 2010.

Trust channels became delivery channels. CCleaner, M.E.Doc, SolarWinds and Kaseya delivered through the vendor relationship. The product is now identity and data, not the host. Cl0p's mass exploitation of MOVEit in 2023 skipped encryption entirely and extorted on stolen data alone. Scattered Spider chose casinos and large enterprises because the payout justified live social engineering of a help desk. Infostealer markets sell session tokens because a token opens the SaaS tenant where the data lives; the Snowflake customer breaches of 2024 are the cleanest case, infostealer credentials, no MFA, about 165 tenants, no host touched. Volt Typhoon is the reminder that one class of adversary is not paid at all and is prepositioning for disruption, and North Korea's Bybit heist of February 2025, about $1.5 billion, is the state revenue line at record scale. For the agent cases the business model is not yet observed; Lecture 2 treats grab-and-go theft and campaign staging as projections, not as a reported economy.

What is new, and what is not. Fileless tradecraft is not new here; the previous period made it standard. The period's additions are three: hands-on intrusion through people and sessions rather than payloads, edge devices as the entry point, and agents as a new actor. Say the "no malware file" part precisely, because the lecture's own definition is at stake: the malicious capability is still there, in hands-on intrusion, built-in tools, exploits and stolen sessions; what is gone is the file that used to carry it. The 2023 Volt Typhoon advisory described a state actor persisting in critical infrastructure using only built-in tools and valid accounts, which prompted dedicated living-off-the-land guidance in 2024. Scattered Spider reached large enterprises the same year through help-desk calls and MFA resets, with SIM swapping among its wider techniques. Infostealers sold session cookies that skipped authentication altogether. Edge devices, which run no EDR, had been an entry point since 2019; in this period they became the main one, and Salt Typhoon showed the same path into the telecoms. In each case the host-based sensor had little to see, because the attacker used the organization's own tools under the organization's own identities.

What did not leave. Say this plainly, because the period's name invites overstatement: most campaigns still start with a file, and the implants, loaders and infostealers sold on criminal markets are files. What changed inside them is the runtime, Go, Rust and .NET rather than C, which keeps the PE format and defeats the analysis toolchain built for C, and, in the newest ones, an LLM call: Talos described NIK C2 in October 2026, a Go remote-access tool with an OpenAI client that bills the victim's own key, and VOLTA, a built-to-order infostealer that sends the stolen bundle to a model to rank the victim's assets. The file stopped being required; it did not become rare.

The user runs the payload. ClickFix lures ask the user to paste a command into a Run dialog or terminal, turning the person into the loader. There is no attachment to scan and the process ancestry looks like the user.

The operating-system row has largely won the host. Driver blocklists, LSA protection on enterprise devices, virtualization-based security and passkeys close most of the previous period's paths by default. That success is part of why the attacker moved to identity, edge devices and people. XZ Utils in March 2024 is the reminder that the host is now also Linux, and that its supply chain can be the way in.

The device supply chain. XCPE, disclosed by Google on 2 November 2026, is the Mirai line arriving at the consumer and the supply-chain row of slide 14 at the device level: a manufacturer built a backdoor into the firmware partition of more than 1.3 million Android TV boxes, designed to pass certification checks, and sold access to affiliates for residential proxies and ad fraud; Google assessed that the affiliates' control domains reached at least 10 million more devices. That is the botnet-for-hire model of 2005, bandwidth as the product, on hardware that can never run an agent. BADBOX (2023) and BADBOX 2.0 (FBI warning, June 2025) were the precedents. No endpoint product answered: the traffic was seen from the network by a home-WiFi vendor and a carrier's research team, and the response was legal action against the control domains and the platform owner banning the manufacturer from certified devices, which is Part 2's point that the fix lands at whatever stage can see the evidence.

The new executable. When a coding agent reads a repository file, or a CRM agent reads a lead record, and acts on an instruction embedded in it (prompt injection: data the agent reads, written to be obeyed as instructions), no classical sensor has anything to classify. The telemetry that matters is the context the agent assembled, the tools it called and the identity it acted under. Autonomous agents operating as attackers add persistence and volume on the other side; reports of agent-orchestrated campaigns began in 2025, before the July 2026 incident. This is the 2017 spill-over again (slide 12), in slower motion: the concentrated offensive capability this time is frontier AI, released commercially and as open weights, lowering the skill floor for everyone. Be precise about the limit, though: unlike the leak of a single exploit, the diffusion is gradual, and the criminal economy around it is not settled yet, which the money row already says. Lecture 2 covers both cases in depth; here they are only the latest point on the curve.

Security products are following again. The CrowdStrike outage of July 2024 showed the cost of the kernel sensor that won the previous period, and Microsoft's resiliency initiative moves endpoint security out of the kernel: a change in where the sensor sits, not in what it sees. ATT&CK's April 2026 release (v19) split off Defense Impairment as a tactic, and the October 2026 release (v20) added Impair Autonomous Defenses, prompt injection against LLM-assisted analysis among its methods: the first time the framework named attacks on the defender's own agents. Identity threat detection, agent observability, guardrails and prompt-injection defenses are the sensor moving into the identity provider and the agent harness. Agentic analysis systems such as Project Ire are the same reasoning capability applied on the defensive side; Lecture 3 covers that.

Each row is something students have just seen, now stated as a break in the model from slide 6, ordered by when it became dominant rather than when it was first seen. Every row has a precedent, and the first row is the clearest case of defense causing the next move. Macro viruses from 1995 and the VBScript worms of 2000–2001 were the first wave of non-executable files; Office macro security levels and Outlook attachment blocking absorbed them. Then the channels blocked the executable itself, and the dates matter because they are earlier than students expect: Outlook in June 2000 and by default from Outlook 2002, Gmail from its first months in 2004 with zip archives included, the mail gateways in between, MSN Messenger in April 2005 after the Bropia and Kelvir worms, Facebook Messages from their launch in November 2010. MyDoom mailed itself in zip archives in January 2004 and Bagle in password-protected zips a month later, with the password shown as an image by March. Kelvir sent a link to its .pif rather than the file, which the messenger filter did not catch, and Koobface spread through social networks by link from 2008. The row now also carries the diversification inside the executable: from about 2020 implants, loaders and ransomware moved to Go, Rust and .NET (BlackCat in Rust in November 2021 is the marker), all still PE files, but each runtime needs its own unpacking, symbol recovery and decompilation, so this break is at extraction as much as at the sensor; Part 2's options slide has the row for it. Make the causal point explicit now that the evidence is on the table. File-centric defense worked: signatures, reputation, cloud lookups, download warnings and code-signing enforcement made delivering an unknown executable expensive, so attackers diversified the file. Sandboxes made the unknown document and dropped executable expensive, so attackers went to memory and built-in tools. EDR made implants visible, so attackers went to identities, vendors and remote-management tools. Operating-system hardening closed the host, so attackers went to people, edge devices and agents. Each row is partly a consequence of winning the previous row.

The second callout is the motive track read across the four periods. Defensive success explains why the attacker had to move; the payout explains where they moved to. When the product was the machine, the attack was a file on the machine. When the product became the organization's willingness to pay, the attack became access to the organization. When the product became identity and data in SaaS, the attack became a token or an instruction. Students who remember only this sentence can reconstruct most of the table.

The figure is the one measurement in Part 1 that states the thesis as a number: the share of CrowdStrike's detections that involved no malware file went from 40 percent in 2018 to 79 percent in 2024 (the 2021 point is the fourth quarter of that year). What did not change. The person as the way in, and the file as a carrier. Phishing is the one initial-access capability that runs unchanged from the executable attachments of 2000 to the help-desk calls and ClickFix lures of 2024; the tracks do not show it because it never moved, and that is why it survives every row of this table. And the file never left: most campaigns still begin with an executable or a document, and the implants, loaders and infostealers sold on criminal markets in 2026 are files, now in Go, Rust and .NET, some with an LLM call inside (slide 13). This table records that the file stopped being required, not that it became rare; a lecture that says "malware is no longer a file" has overstated its own evidence.

In the words of the four questions that close Part 1 (slide 18): the artifact carried the malicious meaning in the file era; the APT era added objective, because the same file meant something different inside a campaign; the access economy moved the meaning to control, since a legitimate tool, a valid token or a real vendor update was malicious only because of who held it; and the agent period adds a controller that is itself a program acting under delegated authority, so control and objective have to be read from the agent's context and actions. Each move is also a move in what evidence the defender needs, which is the second half of the lecture.

Avoid claiming that “fileless” always means literally no disk artifacts. The important distinction is that the primary malicious capability may never appear as a conventional executable file supplied to a scanner. The first row is the mildest break: still a file, no longer an executable, which is why file-based defenses extended rather than collapsed in that period.

Cloud and identity abuse go further: the attacker may realize an objective through legitimate APIs without delivering executable code to the victim host. The last row goes further still: the thing that executes is an instruction consumed by a program that was supposed to be on the defender's side.

Antivirus to sandbox: extraction and detection. Antivirus already reached for unknown files and unknown families with heuristics, generic detections and emulation, but as a preventive control it had to do so at a false-positive rate a blocking product can afford, and the extraction and detection rows still failed on packed, polymorphic and novel files. So the industry added a generation that runs the file instead of parsing it. From about 2011 to 2016 the network and mail sandbox was the premium control, because it judged an object by what it does: exploit documents, zero-days and novel implants arriving by mail and web were caught regardless of packing or signature coverage. Point at the sensor row: the sandbox added no sensor of its own; it borrowed the gateway's and the endpoint's and asked them for the file.

Sandbox to EDR: sensor and acquisition, then everything below. Because the sandbox depends on another product handing it a self-contained object, once the capability was an inline command, a staged payload or a memory-only implant nothing arrived to detonate, and nothing further down a pipeline can repair an empty first row. The answer was the host, where antivirus's hooks already were, and a different premise. By the early 2010s, after Aurora and breach reports measuring dwell time in months (Mandiant's median was 416 days for 2011 and 243 for 2012), defenders accepted that a determined adversary would get past prevention: assume breach. EDR took the same sensor and the same collection as antivirus and changed what happens to the data. Instead of being judged on the host and discarded, it is forwarded, retained and correlated centrally, so detection, investigation, decision and response were rebuilt around a record of activity rather than a verdict on an object. The difference between the two columns starts below the acquisition row, and the decision row carries the preventive-versus-detective difference: antivirus and the sandbox render a verdict on an object before it runs, EDR records activity and alerts after the fact. The name endpoint detection and response was coined in 2013; dwell time, which antivirus never measured, is the metric EDR was built against. That is why EDR survived the attacker's departure from files: it never depended on a file. Students who think of it as "next-generation antivirus" miss that the two answer different questions: "should this object run?" versus "what has already happened on this host?"

Starved by, then the scenario check. The last stage is each generation's exit. The sandbox did not become useless; it became a commodity capability with a narrower role, commodity droppers and malicious documents at machine scale and detonation as one tool among several at investigation scale (Lecture 3 returns to it as a tool an analyst agent calls). EDR has its own column: it sees the host and does not see the attacker's session in a SaaS console, a cloud API call made with a stolen token, or a legitimate remote-management tool doing what it was designed to do; that is where identity telemetry, and the control and objective questions from slide 18, take over. The last Next shows the scenario check. Antivirus and the sandbox see only a legitimate signed driver, nothing malicious handed to either. EDR would record the whole chain, the driver load, the download, the injection into explorer.exe, the document reads and the upload, and fire on the sequence, which is exactly the pattern it was built to detect. That is why the attacker's first move is to disable EDR and antivirus from the kernel with the vulnerable driver (BYOVD, slide 17). The detection surface moves to the tampering itself: kernel attack-surface reduction, tamper protection, and the Defense Impairment tactic ATT&CK added in 2026. The point: no single event is malicious on its own, the sequence is, so the attacker removes the sensor that sees sequences. Say also, without a slide, that EDR is not a next-generation antivirus but a different control, built on the assumption that prevention will fail; the exercise picks both points up.

If asked: what starves a sandbox. It needs a self-contained, detonatable artifact. Inline commands: the PowerShell one-liner is text in a process command line, there is no file to submit. Staged payloads: a stager fetches its second stage only from the real victim; the command-and-control server is geo-fenced, rate-limited or offline when the sandbox asks, and the sandbox records a harmless download attempt. DLL side-loading: the malicious DLL only runs when the legitimate signed host executable loads it from a specific directory layout; submit the DLL alone and nothing happens. Memory-only implants: the implant never exists as a file on any system, and the loader is often legitimate. Evasion: sleeps, environment checks, user-interaction gating and hardware fingerprinting detect the analysis VM itself, which was a generic image, rarely anything like the victim's machine.

If asked: dates. Antivirus dates from the late 1980s; the sandbox as a product from CWSandbox and the first FireEye appliances in the late 2000s, and it became the premium purchase around 2011 to 2013 with WildFire, Lastline and FireEye's IPO; EDR's first products, Carbon Black's sensor and Mandiant's MIR before it, date from around 2011 and earlier, and the name came in 2013.

Defenders had three responses:

  1. Decrypt in the middle. A TLS inspection proxy restores payload visibility for north-south web traffic, but it breaks certificate pinning, raises privacy and legal questions, costs performance, and becomes a high-value target holding every session in plaintext.
  2. Move to metadata. Network detection and response products use endpoints, timing, volume, and TLS fingerprints such as JA3 and JA4. These answer different questions with lower specificity.
  3. Move the sensor to the endpoint. The plaintext still exists where the process encrypts and decrypts it. EDR observes the process, the connection, and the content before encryption.

Be precise about what survived. East-west internal traffic is often still plaintext or inspectable: SMB, Kerberos, LDAP, and remote-management protocols, which is exactly where lateral movement and credential abuse happen. Scanning, DNS without encryption, and beacon timing remain visible. North-south payload signatures are what lost most of their value without decryption. The XCPE takedown of November 2026 is this lineage working: a firmware botnet in 1.3 million set-top boxes, which no endpoint agent could see, was found from the network side by a home-WiFi vendor and a carrier's research team, and taken down at its control domains.

In the recurring scenario the implant download and the uploaded documents are the two beats a network sensor gets a chance at; TLS conceals their content from an intermediate sensor, but the connections, their timing and the destination reputation remain, and a decryption proxy restores the payload. The endpoint still observes PowerShell, the downloads, the document access and the memory activity; metadata and endpoint context answer different questions and often with lower specificity.

Make three points explicit:

  1. The failures were real, and they were all the same failure. Antivirus missed packed and polymorphic files, the sandbox missed staged and memory-only payloads, the IDS missed everything inside TLS, and EDR misses the stolen token and the remote-management tool: in each case the product did what it was built to do and the evidence was no longer where it looked, and the repair happened at the stage in the second column: a sensor on the host or at the identity provider, emulation and decryption at extraction, provenance and behavior at representation, and a better classifier only where the classifier was the stage that broke. Nothing was retired, because each still catches what stays in its field of view, but the premium control of one decade became the commodity control of the next. Say plainly that this is the normal condition of the field, not a story with an ending: every defensive success on this table changed the attacker's behavior, and the next change will break a stage somewhere in this pipeline again. A security product that cannot be re-pointed at new evidence is a product with a shelf life.
  2. The direction is consistent. The sensor moved closer to where the capability executes and closer to who authorized it: from the artifact, to the host, to the identity, to the agent's reasoning trajectory.
  3. The next row is already here. When a coding agent reads a repository file and acts on an instruction in it, no classical sensor has anything to classify. The telemetry that matters is the context the agent assembled, the tools it called, and the identity it acted under. Lecture 2 is built on that row.

If someone asks whether signatures or machine learning are file-only methods, the answer is no, and the detection panel is where to say it. The signature engine that matches byte patterns in files is the same engine that matches YARA rules over process memory in an EDR and content rules over packets in an IDS, and AMSI exists so that it can see script content before the interpreter runs it. Boosted trees over engineered features run over process trees, command lines, memory-region properties and flow and TLS metadata as readily as over PE headers; byte and sequence models have been applied to memory dumps and network payloads; function similarity finds code reuse in a dumped implant as readily as in a dropped file. Each family is tied to what the sensor hands it, not to the file. What is file-centric is the public evidence base: EMBER, SOREL-20M and most of the literature use files because files are what could be collected, labeled and shared at scale. Case A

Case D

The alert is correct and investigated, but isolating the server needs an approval that is unreachable overnight. The upload completes.

Isolation is ordered, but the laptop is off the VPN and the EDR cannot reach it for six hours.

Two points to state while the cases are discussed. First, only some misses can be repaired by retraining the classifier; make students name the failed stage before they propose a larger model, and remember the miss that is not a miss at all, when no malicious activity occurred. Second, a detection is not an outcome: a correct alert that arrives too late, lacks recoverable evidence, or cannot trigger containment is not equivalent to stopping the attack. Cases D to F make that second point concrete.

A and C together carry the memory nuance. Once an EDR sees executable private memory or a protection change, that is observable and is not a verdict: PowerShell runs on .NET and the CLR legitimately compiles code into process memory at run time, as do browsers, JVMs and instrumentation. Visibility is not distinguishability, and distinguishability is not a verdict. The defender needs the context the representation has to keep: identity and process ancestry, command and script content, network provenance, the memory region's provenance and backing, control transfers and follow-on behavior. That is why A is a sensor failure and C a representation or classifier one: once the sensor sat on the host the problem moved down the pipeline, it did not disappear.
